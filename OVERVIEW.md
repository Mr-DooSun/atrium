Replaces the sidebar list with a tree of workspaces and agents built from Paseo's parent agent records. A sub-agent that runs in its own worktree workspace is shown under the agent that started it, at any depth, instead of as a separate top-level row. Agents in the same workspace are nested under their parent agent. A workspace with a single root agent shows that agent's children directly under the workspace row.

Each workspace row keeps its status, branch and diff counts, and shows how many agents below it are running. A session also shows its parent's worktree name and branch when they run in different worktrees. A running workspace or agent has a spinning ring; agents waiting for permission are amber and failed ones red. Connector lines run from each project tile down to its sessions and from each agent to the agents it started. Each row leads with its provider's mark in brand color (the Claude Code bot, Codex, Antigravity; custom providers named after one, such as claude-pb1, use its mark) and ends with its status. rows fold and unfold, and a folded row shows how many entries it hides. Hovering a workspace row shows a pencil to give it a display name instead of its folder name; the name is the workspace's Paseo title, so other clients show it too, and an empty name goes back to the folder name.

Each project has a stable accent derived from its folder, with theme-aware colors on its header and connectors. Spacing and dividers distinguish adjacent projects. A project stays in the tree after its last session is archived, with a row to start a new chat in it. Hovering a project header shows a button to remove it from Paseo (a long press on mobile), the same as Paseo's own remove project: after a confirmation that counts its sessions and any still running, its sessions are archived and its files stay on disk. Adding the folder in Paseo again brings it back.

Projects are listed most recent work first until you set your own order. On desktop, drag a project header up or down and drop it where a line shows; a click still folds it. Sessions drag the same way among the sessions beside them, at any depth, and carry the sessions under them; new top sessions show first and new sub-sessions last. On mobile, a long press on a project header opens a menu with reordering and removing; reordering gives every header up and down buttons, and Done ends it. The order is kept on the daemon by folder, so every client shows it and a project added again keeps its place; a project not placed yet shows at the top, and Reset goes back to most recent first.

A General section stays pinned at the bottom of the sidebar, below the tree, for conversations that belong to no project. Paseo agents always run in a folder, so these run in `~/.paseo-chat` on the daemon, which the plugin creates on first use; that folder's workspaces are left out of the tree. Its labels follow the app language, in every language Paseo offers, and fall back to English for any other. The new chat button opens Paseo's own new workspace screen for that folder, so the provider picker works as usual. Chats are listed most recent first, and archiving a chat also archives its workspace when nothing else runs there.

Choose it under Settings, Sidebar, Sidebar view. Background helpers and closed agents are hidden. Fold state is not saved across reloads.

The plugin extends Paseo's built-in usage panel with account cards for non-default Claude and Codex accounts on the host. Each card shows plan, rate-limit windows, reset times, email, and local token totals for 5-hour/today/7-day periods. Cards for expired or rejected logins carry a `refreshedBy` hint so Paseo shows its re-login prompt. For Claude accounts, rate limits are fetched from Anthropic's OAuth API; for Codex, they come from local session logs only. It replaces zerosub. For details, see [docs/usage-monitor.md](docs/usage-monitor.md).
